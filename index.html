Privacy Policy

whoop-mcp · Last updated 13 November 2026

whoop-mcp is a personal tool, run by one person on their own computer, that reads that same person’s WHOOP data. It has no other users, no server, and no account system. It collects nothing from anyone else.

Who this covers

whoop-mcp (“the software”) is a single-user, locally-installed program. The only person whose data it accesses is the operator who installed it and authorized it against their own WHOOP account. The software is not offered as a service to the public, hosts no shared infrastructure, and has no mechanism by which a third party could use it or submit data to it.

What data is accessed

After the operator authorizes the software against their own WHOOP account, it may read the following from the WHOOP API, within the scopes the operator granted:

  • Profile basics: name and email address on the WHOOP account
  • Body measurements: height, weight, maximum heart rate
  • Physiological cycles: daily strain, energy expenditure, average and maximum heart rate
  • Recovery: recovery score, heart rate variability, resting heart rate, blood oxygen, skin temperature
  • Sleep: duration, stages, efficiency, consistency, respiratory rate, sleep need
  • Workouts: sport, duration, strain, heart rate, energy expenditure, distance, elevation, time in heart-rate zones

The software only reads. It does not create, modify, or delete anything in the WHOOP account.

Where that data goes

Data is requested directly from WHOOP’s API over HTTPS to the operator’s own computer. There is no intermediate server, hosted backend, or database operated by this project, and no copy of the data is retained anywhere by its author.

The software’s purpose is to make this data readable by an AI assistant running on the operator’s computer. When the operator asks a question that calls one of its tools, the data returned by that tool is passed to the assistant and therefore to that assistant provider’s API, under that provider’s own privacy terms. This is the operator’s deliberate choice each time they ask such a question. No data is sent anywhere else: there is no analytics, telemetry, crash reporting, advertising, or third-party data sharing of any kind.

Credentials and storage

OAuth tokens are stored in a single file on the operator’s computer (.data/tokens.json), with filesystem permissions restricting it to that user account. WHOOP client credentials are stored in a local .env file. Neither file is transmitted, synced, or committed to version control. WHOOP data itself is not cached or written to disk; it is fetched on demand and held only in memory for the duration of a request.

Retention and deletion

Because no WHOOP data is stored, there is nothing to delete beyond the stored credentials. The operator can end all access at any time by deleting .data/tokens.json, and can revoke the authorization entirely from their WHOOP account settings or by having the software call WHOOP’s de-authorization endpoint. Revoking access immediately prevents any further reads.

Children

The software is not directed at children and is usable only by the person who installs and authorizes it on their own machine.
